# AMP · Заказы склада

Мобильное и компьютерное приложение для общей истории заказов. Проект Firebase: `sklad-18f38`.

## Возможности

- Вход по почте и паролю; Google-вход оставлен для прежних аккаунтов и перехода на пароль. Письма для сброса пароля не отправляются.
- Создание сотрудника администратором с заданными почтой и паролем; изменение роли и доступа сотрудников.
- Самостоятельная смена пароля сотрудником в меню профиля.
- Комментарии к заказам доступны всем ролям; текст обязателен, артикул для дефекта и фотографии можно приложить по необходимости.
- Администратор может удалять заказы; перед удалением карточка и все записи попадают в отдельный архив, доступный из меню профиля.
- Общая история заказов и записей с обновлениями в реальном времени.
- Роли кладовщика, менеджера и директора.
- Фото к комментариям хранятся в Firestore вместе с записью.

## Первый администратор

В Firebase Console → Authentication → Sign-in method включите Email/Password. Оставьте Google включённым, если нужно сохранить вход для уже существующих пользователей.

Для первого администратора используйте один из вариантов:

- Если Google-аккаунт уже зарегистрирован, войдите на сайт через Google и скопируйте UID из Authentication → Users.
- Иначе откройте Authentication → Users → Add user и создайте учётную запись с почтой и паролем.

В Firestore Database → Data создайте документ `users/{UID}` с полями:

- `displayName` (string) — имя;
- `email` (string) — та же почта;
- `role` (string) — `warehouse`;
- `active` (boolean) — `true`;
- `admin` (boolean) — `true`.

В приложении администратор открывает профиль → «Учётные записи сотрудников» → «Добавить сотрудника», задаёт имя, почту, пароль и роль. Письма не отправляются. Минимальная длина пароля — 6 символов. После входа сотрудник может поменять его в меню профиля → «Сменить пароль». Старые пользователи Google могут войти через кнопку Google и в меню профиля нажать «Задать пароль для входа»; после привязки им доступны оба способа входа и смена пароля.

## Удаление заказов и правила Firestore

После изменения правил опубликуйте их в Firebase Console → Firestore Database → Rules или из корня проекта выполните `firebase deploy --only firestore:rules`. Без новых правил приложение не сможет записать архив и удалить карточку.

## Освободить занятую почту

Удаление чужой учётной записи Firebase Authentication из браузера нельзя безопасно выполнить без серверной функции. Чтобы бесплатно удалить старый аккаунт и зарегистрировать адрес заново:

1. Firebase Console → Authentication → Users: найдите запись по почте и удалите её.
2. Найдите соответствующий профиль в Firestore → `users` и удалите документ с тем же UID.
3. В приложении создайте сотрудника с нужной почтой и новым паролем.

Если удалить только профиль Firestore, старая запись Authentication останется и адрес будет считаться занятым. Если удалить только запись Authentication, перед повторным созданием нужно также удалить старый документ профиля, иначе останется осиротевшая запись.

Cloud Functions и платный план Blaze для регистрации сотрудников и смены пароля не используются. Сайт на GitHub Pages публикуется отдельно; Firebase Hosting не требуется.

## Установка приложения

Приложение можно установить из браузера, отдельный APK для этого не нужен:

- На компьютере в Chrome или Edge откройте сайт и выберите «Установить приложение» в меню браузера.
- На Android откройте сайт в Chrome и выберите «Установить приложение» или «Добавить на главный экран».
- На iPhone откройте сайт в Safari → «Поделиться» → «На экран Домой».

Для уведомлений в фоне включите push в центре уведомлений приложения на каждом устройстве. Дальше потребуется один раз добавить публичный Web Push сертификат Firebase и секрет сервисного аккаунта в GitHub Actions; инструкция ниже.

## Фото и уведомления

Фото сохраняются как сжатые данные в Firestore (до пяти снимков на запись). При росте объёма фотографий регулярно экспортируйте Firestore и рассмотрите перенос изображений в Cloud Storage.

Открытые приложения получают изменения и показывают уведомления. Системные уведомления работают, пока вкладка/приложение продолжает работать в фоне. Push-уведомления, когда приложение закрыто, требуют Firebase Cloud Messaging.

### Настроить фоновые push-уведомления

1. Firebase Console → Project settings → Cloud Messaging → Web Push certificates → создайте/скопируйте ключ. В `firebase-config.js` замените `ADD_WEB_PUSH_CERTIFICATE_KEY_HERE` на этот публичный ключ.
2. Firebase Console → Project settings → Service accounts → создайте закрытый ключ JSON для сервисного аккаунта.
3. На GitHub откройте Settings → Secrets and variables → Actions → New repository secret. Название: `FIREBASE_SERVICE_ACCOUNT_JSON`; значение: всё содержимое JSON-файла. Не добавляйте этот файл в репозиторий.
4. Опубликуйте новые Firestore Rules из `firestore.rules` в Firebase Console.
5. Обновите сайт и на каждом телефоне/компьютере откройте центр уведомлений → «Разрешить на этом устройстве» и разрешите уведомления браузера.

Отправитель запускается GitHub Actions примерно раз в пять минут. Раннеры бесплатны для публичного репозитория. Уведомления о заказах и комментариях отправляются на устройства всех активных сотрудников, включая другие устройства автора события. Поэтому автор с компьютера получит уведомление на свой подключённый телефон. Доставка зависит от разрешений браузера, сети и поддержки Web Push устройством.
