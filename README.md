# AMP · Заказы склада

Мобильное и компьютерное приложение для общей истории заказов. Проект Firebase: `sklad-18f38`.

## Уже подключено

- Firebase Authentication с входом по почте и паролю;
- Cloud Firestore с общей историей заказов и записей;
- моментальное обновление открытых приложений и уведомления внутри приложения;
- отдельные права кладовщика, менеджера и директора;
- удалять карточки и записи может только директор;
- фото сжимаются и сохраняются с записью заказа в Firestore, поэтому пока не нужен Cloud Storage.

## Первый администратор

Только для первого входа:

1. В Firebase Console откройте Authentication → Users → Add user и создайте собственную учётную запись.
2. Скопируйте UID из списка пользователей Authentication.
3. В Firestore Database → Data создайте коллекцию `users`, документ с ID, равным UID.
4. Добавьте поля: `displayName` (string), `role` (string `warehouse`), `active` (boolean `true`), `admin` (boolean `true`).

После входа администратор добавляет сотрудников из приложения: профиль → «Учётные записи сотрудников» → «Добавить сотрудника». Firebase отправляет сотруднику письмо для установки пароля (сам пароль в письме не передаётся). Если письмо не пришло, проверьте спам и шаблон сброса пароля в Firebase Console → Authentication → Templates; приложение покажет код Firebase и этап, на котором произошла ошибка. Если аккаунт и профиль уже созданы, на экране входа можно отправить письмо повторно кнопкой «Забыли пароль?». Там же доступ сотрудника можно отключить и назначить роли кладовщика, менеджера или директора. Только роль директора даёт право удалять карточки и записи.

## Фото и уведомления

Фото сохраняются как сжатые данные в Firestore (до пяти снимков на запись; приложение автоматически ограничивает размер). Это подходит для старта и небольшого потока заказов. Перед активным использованием регулярно экспортируйте Firestore; при росте объема фотографий перенесите их в Cloud Storage.

Открытые приложения получают изменения и показывают уведомление. Если браузеру разрешить системные уведомления, он сможет показывать их, пока вкладка/приложение продолжает работать в фоне. Для push, когда приложение закрыто, нужен доверенный сервер отправки Firebase Cloud Messaging (например Cloud Functions). Его пока нет. Cloud Storage, Cloud Functions и платный план не включены.

## Firebase CLI

Чтобы опубликовать правила и Hosting из этой папки, установите Firebase CLI и выполните вход в свой Firebase аккаунт. Для сайта на GitHub Pages Hosting-команда не нужна:

```powershell
firebase deploy --only firestore:rules
```

Не выполняйте общий `firebase deploy`, если не планируете отдельно настраивать и оплачивать Cloud Storage/другие облачные сервисы.
