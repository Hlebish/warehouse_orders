# AMP · Заказы склада

Мобильное и компьютерное приложение для общей истории заказов. Проект Firebase: `sklad-18f38`.

## Уже подключено

- Firebase Authentication с входом по почте и паролю;
- Cloud Firestore с общей историей заказов и записей;
- моментальное обновление открытых приложений и уведомления внутри приложения;
- отдельные права кладовщика, менеджера и директора;
- удалять карточки и записи может только директор;
- фото сжимаются и сохраняются с записью заказа в Firestore, поэтому пока не нужен Cloud Storage.

## Первый администратор

Создайте первого администратора через экран входа Google:

1. В Firebase Console → Authentication → Sign-in method включите Google.
2. Войдите на сайт через Google; Firebase создаст запись Authentication.
3. Скопируйте UID этой записи из Authentication → Users.
4. В Firestore Database → Data создайте `users/{UID}` с полями `displayName` (string), `email` (string), `role` (string `warehouse`), `active` (boolean `true`), `admin` (boolean `true`).

Вход в приложение выполняется через Google. Администратор добавляет сотрудника в приложении: профиль → «Учётные записи сотрудников» → «Добавить сотрудника», указывает Google-почту и роль. При первом входе с этой почтой профиль будет создан автоматически. Пароли и письма для установки пароля не используются. Старые аккаунты по почте и паролю можно открыть через раскрывающуюся форму на экране входа и привязать Google в меню профиля.

В разделе учётных записей можно удалить Firebase-аккаунт по почте, в том числе если его профиль отсутствует в списке. Это освобождает адрес для повторного добавления. Для этого в проекте развёрнуты Cloud Functions. Включите Google как способ входа в Firebase Console → Authentication → Sign-in method, затем разверните серверные функции и правила:

```powershell
firebase deploy --only firestore:rules,functions
```

Для Cloud Functions Firebase требует план Blaze. До развёртывания функций Google-вход появится на сайте, но создание профилей, удаление аккаунтов и привязка новых сотрудников работать не будут.

## Фото и уведомления

Фото сохраняются как сжатые данные в Firestore (до пяти снимков на запись; приложение автоматически ограничивает размер). Это подходит для старта и небольшого потока заказов. Перед активным использованием регулярно экспортируйте Firestore; при росте объема фотографий перенесите их в Cloud Storage.

Открытые приложения получают изменения и показывают уведомление. Если браузеру разрешить системные уведомления, он сможет показывать их, пока вкладка/приложение продолжает работать в фоне. Для push, когда приложение закрыто, нужен Firebase Cloud Messaging.

## Firebase CLI

Чтобы опубликовать правила и функции из этой папки, установите Firebase CLI и выполните вход в свой Firebase аккаунт:

```powershell
firebase deploy --only firestore:rules,functions
```

Для сайта на GitHub Pages команда Hosting не нужна. Не выполняйте общий `firebase deploy`, если не планируете отдельно настраивать Cloud Storage и другие облачные сервисы.
